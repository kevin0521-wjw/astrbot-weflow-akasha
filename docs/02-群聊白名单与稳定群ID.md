# 02 · 群聊白名单与稳定群 ID

## 需求

让 bot **只在指定群里生效**，其他群/私聊保持沉默。

## 方案选择

| 方案 | 结果 |
|------|------|
| 插件市场找现成「白名单群聊管理插件」 | ❌ 没有合适的 |
| 自己写插件（`grouplist_helper`） | ❌ 已删除，没必要 |
| **AstrBot 内置 `id_whitelist`** | ✅ 采用 |

## 配置

文件：`~/.astrbot/data/cmd_config.json`

```jsonc
{
  "platform_settings": {
    "enable_id_white_list": true,
    "id_whitelist": [
      "default:GroupMessage:111111111",
      "default:GroupMessage:222222222",
      "default:GroupMessage:1757289731"
    ]
  }
}
```

| 键 | 语义 |
|----|------|
| `enable_id_white_list` | 总开关 |
| `id_whitelist` | 放行名单；**空列表 = 不检查（全放行）**，不是全拦 |

会话 ID 格式：`default:GroupMessage:<整数群ID>`，其中 `<整数群ID>` 由 bridge 用群 sessionId 算出。

### 配套补丁：私聊放行

白名单开启后私聊会被一并拦截。给 AstrBot `whitelist_check/stage.py` 增加
`FRIEND_MESSAGE`（私聊）直接放行的分支，备份为 `stage.py.bak_20260805`。

## 核心 Bug：群 ID 不稳定导致白名单失效

### 症状

bridge 每重启一次，AstrBot 侧白名单就整体失效，要重新配置。

### 根因

```python
# bridge/state.py —— ❌ 修复前
def _wxid_to_int(wxid: str) -> int:
    return abs(hash(wxid)) % (2**31)
```

Python 对 `str` 的内置 `hash()` 默认启用 **哈希随机化**（`PYTHONHASHSEED=random`）。
同一个字符串，**在不同进程里 `hash()` 结果不同**：

```text
进程 A: hash("某群A") →  -4123456789012345678
进程 B: hash("某群A") →   7654321098765432109   ← 变了！
```

于是 `default:GroupMessage:<id>` 每次启动都变，写死在 `id_whitelist` 里的 ID 自然全部失配。
（这也解释了为什么「刚才还好的，重启就不行了」。）

### 修复

```python
# bridge/state.py —— ✅ 修复后
def _wxid_to_int(wxid: str) -> int:
    """将微信 wxid 映射为稳定的整数 ID。

    使用 zlib.crc32 代替内置 hash()：
    - 内置 hash(str) 受 PYTHONHASHSEED 影响，进程重启后结果会变化，
      导致 OneBot 会话 ID 不稳定、白名单失效。
    - crc32 是确定性算法，跨进程/跨重启结果一致。
    """
    import zlib
    return zlib.crc32(wxid.encode("utf-8")) & 0x7FFFFFFF
```

`& 0x7FFFFFFF` 保证结果落在 OneBot 常用的 32 位正整数范围内。

### 验算

```python
import zlib
zlib.crc32("99999999@chatroom".encode()) & 0x7FFFFFFF   # → 1757289731
```

所以该群对应的会话 ID 是 `default:GroupMessage:1757289731`。

> 也验证了「换一个稳定算法」以外的做法都不可靠：
> 存映射表、写死 ID 都会因为 ID 本身会变而失效，**必须从源头让 ID 确定**。

## 踩坑记录

| 坑 | 说明 |
|----|------|
| **群 ID 由群名/sessionId 算出** | WeFlow 一开始只给群 ID（`99999999@chatroom`），后来解析出真实群名后，算出的是另一个整数 → 需重新加白名单 |
| 群名带副本后缀 | WeFlow 有时把群名给成 `某某群 (2)`，bridge 用 `re.sub(r'\s*\(\d+\)\s*$', '', name)` 剥掉，保证同一群名稳定 |
| 空列表语义 | 是「不检查」不是「全拦」，排查时别搞反 |
| 白名单 ≠ 回复策略 | 白名单只管「能不能进 AstrBot」；「要不要回复/@才回复」是另一层（见回滚功能复盘） |
| AstrBot 数据目录 | 桌面版 `~/.astrbot/data` vs 手动启动的工作目录，改错文件会「改了没效果」 |

## 排查清单

1. bridge 日志里搜 `📌 群映射:` —— 会打印 `sessionId / 群名 / group_id / 会话ID`。
2. 拿日志里的 `group_id` 核对 `id_whitelist` 是否一致。
3. 不一致 → 确认是否发生过群名解析变化；重新加白名单 + 重启 AstrBot 后端。
4. 一致但仍不回复 → 检查是否被 `mention` 模式挡掉（需 @ 才回）。
