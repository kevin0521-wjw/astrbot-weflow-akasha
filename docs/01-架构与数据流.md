# 01 · 架构与数据流

## 组件职责

| 组件 | 角色 | 默认地址 | 备注 |
|------|------|----------|------|
| PC 微信 | 消息出入口 | —— | 必须**已登录且窗口可被 UIA 找到** |
| WeFlow | 微信消息抓取与发送网关 | `127.0.0.1:5031` | 提供 SSE 推送 + 发送 API + 附件下载 |
| bridge | 协议翻译器 | Web 面板 `127.0.0.1:8766` | WeFlow ↔ OneBot v11 双向转换 |
| AstrBot | LLM 编排 + 人格 + 插件 | aiocqhttp `ws://127.0.0.1:11229/ws` | bridge 作为 WS **客户端**连它 |
| 文本 LLM | 生成回复 | 云端 API | 如 DeepSeek，纯文本即可 |
| 视觉模型 | 图片转文字描述 | Ollama `127.0.0.1:11434` | 如 `llava:7b` |

## 收消息（微信 → LLM）

```
1. 微信收到新消息
2. WeFlow 通过 SSE 推送 JSON：
   {
     "sessionId":   "群 sessionId 或联系人 id",
     "sessionType": "group" | "private",
     "groupName":   "群名（私聊为空）",
     "sourceName":  "发送者昵称",
     "content":     "文本内容 / [图片] / [表情] / [语音]",
     "talkerId":    "会话标识"
   }
3. bridge.WeFlowBridge.add_to_buffer(data)
   ├─ should_ignore() 过滤自己发的消息、非白名单内容
   ├─ 群消息：剥掉群名尾部的 ` (123)` 副本后缀 → base_name
   ├─ 按 contact 聚合进缓冲区，启动 buffer_seconds(默认 5s) 定时器
   └─ 若 content == "[图片]" → 转 process_image_message()
4. 计时器到点 → process_sender(contact)
   ├─ 把多条缓冲消息拼成一行行 `发送者: 内容`
   ├─ 计算 group_id = _wxid_to_int(sessionId)
   ├─ 记录映射 state._ob_id_to_contact[group_id] = 群名   ← 回程靠它找目标
   └─ make_message_event() → push_event() 经 WebSocket 推给 AstrBot
```

### 群 vs 私聊

| | 群聊 | 私聊 |
|--|------|------|
| `message_type` | `group` | `private` |
| ID 来源 | `group_id = _wxid_to_int(sessionId)` | `user_id = _wxid_to_int(发言人)` |
| 会话 ID（AstrBot 侧） | `default:GroupMessage:<group_id>` | `default:FriendMessage:<user_id>` |
| mention 模式 | 消息段前加 `{"type":"at"}` | 不适用 |

## 发消息（LLM → 微信）

AstrBot 通过 WS 下发 API 调用，bridge 在 `ob_protocol.py::_handle_ob_api` 处理：

| action | 说明 |
|--------|------|
| `send_msg` / `send_private_msg` / `send_group_msg` | 发消息（文本 / 图片 / 表情） |
| `get_group_member_info` | 取群成员信息 |

**关键实现细节**：

1. **先回响应再处理消息**。OneBot 要求 `echo` 配对，bridge 收到请求后立刻回 `{"status":"ok","retcode":0,"echo":...}`，
   否则 AstrBot 侧超时。响应带 10 次重试（间隔 0.5s），应对 WS 短暂断连。
2. **`group_id` → 微信联系名**：靠收消息阶段写入的 `state._ob_id_to_contact` 反查。
3. **文本**：经 `_split_long_text` 切分后逐段 `send_text`。
4. **图片**：
   - `base64://` 前缀 → 解码写临时文件 → `send_image` → 用完删除；
   - 否则当文件名，在 `astrbot_attachments/` 及其 `wechat_images/` 子目录下查找。
5. **表情（`face` 段）**：当前实现发送字面量 `[表情]`（**上游原始行为**，见 [07-回滚功能复盘](07-回滚功能复盘.md)）。

## 发送通道：UIA 纯键盘模拟

```
send_text(contact, text)
  ├─ 剪贴板写入 text（pyperclip）
  ├─ UIA 定位并激活微信窗口（_ensure_window → _find_window）
  ├─ Ctrl+F 搜索框 → 输入联系人名 → Enter 进入会话
  ├─ Ctrl+V 粘贴 → Enter 发送
  └─ 返回 True / False

send_image(contact, path)
  └─ 同上，但用剪贴板写入图片（CF_DIB）而非文本
```

> 因为走的是**真实键盘/剪贴板模拟**，所以：
> - 微信窗口必须保持可被 UIA 定位（不能只在托盘里）；
> - 发送期间会抢焦点，机器上最好别同时手动操作微信。

## AstrBot 侧的配置要点

| 配置 | 位置 | 用途 |
|------|------|------|
| `enable_id_white_list` / `id_whitelist` | `~/.astrbot/data/cmd_config.json` → `platform_settings` | 群聊白名单 |
| `prompt_prefix` | 同上 → `provider_settings` | 输出简短/分段约束 |
| `default_personality` | AstrBot WebUI → 人格 | 选用的「人格」（如「派蒙」） |
| 管理员列表 | AstrBot WebUI → 设置 → 管理员配置 | 插件 `PermissionType.ADMIN` 校验依据 |

> ⚠️ **数据目录陷阱**：AstrBot **桌面版**用 `~/.astrbot/data`；
> 用命令行手动跑 `launch_backend.py` 会用**工作目录下的 `backend/data`**（空库），
> 表现为「人格/配置突然消失」。定位问题时先确认跑的是哪种启动方式。
