# 03 · 图片识别与表情处理

## 核心认知：主模型是纯文本也能识图

很多人第一反应是「DeepSeek 是纯文本模型，是不是要换成 qwen-VL？」——**不需要**。

采用**两段式**架构：

```
图片 ──► 视觉模型（LLaVA 7B / 多模态 API）──► 一段文字描述 ──► 文本 LLM（DeepSeek）──► 回复
         「看图」这一步                      「翻译」                   「说话」这一步
```

| 环节 | 模型 | 职责 | 需要多模态吗 |
|------|------|------|--------------|
| 看图 | Ollama + `llava:7b`（本地） | 把图变成文字描述，如「一张游戏截图，角色站在森林里」 | ✅ |
| 回复 | DeepSeek（纯文本） | 只读描述文字，按人格风格回复 | ❌ |

**想提升识别质量 → 只换视觉模型**（如本地 `qwen2.5-vl`、云端 GLM-4V），主模型一行都不用改。
换主模型为多模态反而要改桥接的传图格式，工作量大。

## 收图链路

```
1. WeFlow SSE: { "content": "[图片]", "sessionId": "...", ... }
2. bridge_core.WeFlowBridge.add_to_buffer()
      if content == "[图片]":
          threading.Thread(target=self.process_image_message, args=(data,)).start()
3. process_image_message(data)
      a. 注册 pending 状态（等描述完成前先占位）
      b. image_path = self._fetch_wechat_image(session_id)     ← 从 WeFlow 下载到本地
      c. caption = caption_image_via_ollama(image_path)        ← 生成文字描述
      d. 描述以 [图片: <caption>] 注入消息缓冲区
      e. img_event.set() 放行，让缓冲计时器继续
4. 缓冲区到点 → 作为**普通文字消息**推给 AstrBot
```

### 下载环节 `_fetch_wechat_image`

- 调 WeFlow `GET /api/v1/messages` 找到该条消息的 `mediaUrl`；
- 下载并保存到 `config.ASTRBOT_ATTACHMENTS/wechat_images/`。

> ⚠️ **最常见的失败原因**：`astrbot_attachments` 还是示例路径（如 `/path/to/astrbot/attachments`）
> 而不是本机真实目录 → 目录不存在 → 下载失败 → 后续无描述。
> 改成真实路径（例：`C:\AstrBot\data\attachments`）即可。

### 描述环节 `caption_image_via_ollama`

虽然函数名叫 `..._ollama`，实际支持**两种后端**，由 `image_caption_provider` 切换：

```python
if config.IMAGE_CAPTION_PROVIDER == "openai":
    # OpenAI 兼容：POST {API_BASE}/chat/completions
    # content = [ {type:text, text:PROMPT}, {type:image_url, url:"data:image/jpeg;base64,..."} ]
else:
    # Ollama 原生：POST {OLLAMA_BASE_URL}/api/generate
    # { "model": MODEL, "prompt": PROMPT, "images": [b64], "stream": false }
```

| 配置项 | 说明 | 示例 |
|--------|------|------|
| `image_caption_provider` | `ollama` / `openai` | `ollama` |
| `image_caption_model` | 视觉模型名 | `llava:7b` |
| `image_caption_api_base` | OpenAI 兼容时用 | `https://api.xiaomimimo.com/v1` |
| `image_caption_api_key` | 同上 | `sk-...` |
| `image_caption_prompt` | 描述提示词 | `请用中文简短描述这张图片的内容` |
| `ollama_base_url` | Ollama 地址 | `http://127.0.0.1:11434` |
| `ollama_timeout` | 超时（秒） | `60` |

这些都能在 Web 面板 → **基础设置** 里改，**保存即时生效，无需重启**。

## 部署 Ollama（本机实录）

| 项 | 值 |
|----|----|
| 安装包 | `OllamaSetup.exe` **v0.32.5**（约 1.46 GB，内含 CUDA 运行时，无需另装 CUDA Toolkit） |
| 安装路径 | `%LOCALAPPDATA%\Programs\Ollama\ollama.exe` |
| 默认端口 | `11434` |
| 拉模型 | `ollama pull llava:7b` |
| 显卡 | RTX 5060 8GB 可跑 llava:7b |

### 国内加速

无 `~/.ollama/config.json` 时，写：

```json
{ "registry": { "mirrors": { "registry.ollama.ai": "https://ollama.modelscope.cn" } } }
```

实测拉取速度可达 ~12 MB/s。
（若 `OLLAMA_HOST` 被改过端口，记得让 `config.json` 里的 `ollama_base_url` 与之对齐。）

## 表情处理现状

| 方向 | 现状 |
|------|------|
| 收（微信 → AstrBot） | 表情消息按 `[表情]` 文本占位；**动图/表情包走的是图片链路**，会被视觉模型描述后交给 LLM |
| 发（AstrBot → 微信） | `face` 段 → 发送字面量 `[表情]`（**上游原始行为**） |

⚠️ 曾实现过完整方案（`emoji_map.py`：QQ face ID 0~246 → 中文描述映射，`face`/`mface` 查表转文字），
但**已回滚**。详见 [07-回滚功能复盘](07-回滚功能复盘.md)。

## 常见故障定位

| 现象 | 检查点 |
|------|--------|
| 图片完全没反应 | WeFlow 是否在跑？SSE 是否连通？日志有没有 `🖼️` |
| 有 `[图片]` 但无描述 | `astrbot_attachments` 是不是真实路径 |
| 描述超时 | Ollama 是否在跑（`ollama list`）、模型是否已 pull、端口是否一致 |
| 描述乱码/不相关 | 换更强的视觉模型，或调整 `image_caption_prompt` |
| 识别质量差 | 只换视觉模型即可，主 LLM 不用动 |
