# 04 · 输出简短与自动分段

## 需求

> 「怎么使 bot 的输出简短，如果有超过两行的让他分段输出」

两个要求：
1. **简短** —— 别长篇大论；
2. **分段** —— 内容确实多时，切成多条消息发，而不是一坨。

## 双层方案

| 层 | 位置 | 作用 | 特点 |
|----|------|------|------|
| 提示词层 | AstrBot `provider_settings.prompt_prefix` | 从**生成侧**约束，让模型少说话 | 柔性，靠模型自觉 |
| 代码层 | `bridge/ob_protocol.py::_split_long_text` | 从**发送侧**兜底强制切分 | 刚性，一定生效 |

两层都要，缺一不可：只靠提示词模型可能不听；只靠代码会切得生硬、且白花 token。

## 第一层：提示词约束

文件：`~/.astrbot/data/cmd_config.json` → `provider_settings.prompt_prefix`

追加内容大意：

```
【输出要求】
- 回复尽量简短，控制在两行以内
- 内容较多时自动分段，每段不超过两行，段与段之间空一行
- 不要输出 markdown 标题、代码块等富文本
```

> 附带好处：微信侧不渲染 Markdown，禁止富文本能避免满屏 `##`、`**`。

## 第二层：代码兜底分段

`bridge/ob_protocol.py`：

```python
def _split_long_text(text: str, max_lines: int = 2) -> list[str]:
    """将长文本按行拆分，每段最多 max_lines 行（2026-08-05 自定义）。"""
    lines = text.split("\n")
    # 去掉首尾空行
    while lines and not lines[0].strip():
        lines.pop(0)
    while lines and not lines[-1].strip():
        lines.pop()
    if len(lines) <= max_lines:
        return [text] if text.strip() else []
    chunks = []
    for i in range(0, len(lines), max_lines):
        chunk = "\n".join(lines[i:i + max_lines]).strip()
        if chunk:
            chunks.append(chunk)
    return chunks
```

接入点（`_handle_ob_api` 的 `text` 分支）：

```python
if seg_type == "text":
    text = seg_data.get("text", "")
    if text:
        # 2026-08-05 自定义：长文本自动分段发送（每段最多 2 行）
        for chunk in _split_long_text(text, max_lines=2):
            if not chunk.strip():
                continue
            sent = await asyncio.to_thread(state.sender_instance.send_text, contact, chunk)
            if sent:
                log.info(f"[OB11] 文字已发送至 {contact}: {chunk[:50]}")
            else:
                log.warning(f"[OB11] 文字发送失败 {contact}: {chunk[:50]}")
```

### 设计细节

| 细节 | 原因 |
|------|------|
| 按**换行**切，不按字数切 | 换行是模型自己的语义边界，切出来更自然 |
| 先剥首尾空行 | 避免发出只有空白的「空气消息」 |
| `len(lines) <= max_lines` 直接返回原文 | 符合预期时**不做任何改动**，保留原始换行 |
| 空 chunk 跳过 | `'\n\n\n'` 这类切出来是空串，发出去就是空消息 |
| 每段单独 `send_text` | UIA 发送以「Enter」结束，天然一条一段 |

## 副作用与注意点

| 现象 | 说明 |
|------|------|
| 「一条回复 = 多条微信消息」 | 设计如此。若嫌吵，把 `max_lines` 调大到 3~4，或只靠提示词层 |
| UIA 发送期间抢焦点 | 分段越多，发送耗时越长（每段都要 Ctrl+F 搜联系人 → 粘贴 → Enter） |
| 与 `buffer_seconds` 无关 | 缓冲是**收**消息侧，分段是**发**消息侧，不要混淆 |

## 调参建议

| 目标 | 做法 |
|------|------|
| 更安静 | `prompt_prefix` 里加强约束；`_split_long_text(..., max_lines=4)` |
| 更碎、更像真人打字 | `max_lines=1`（每行一条） |
| 完全不要自动切分 | 把 `_split_long_text` 调用换成直接 `send_text(contact, text)` |
